# Разбор 1.7 — amortized growth

При doubling resizes происходят примерно при переходах:

```text
1 -> 2 -> 4 -> 8 -> 16 -> 32
```

Чтобы дойти до 20 элементов, копирования на resize затронут примерно:

```text
1 + 2 + 4 + 8 + 16 = 31 элемент
```

Это линейный порядок относительно итогового `n=20`.

При `capacity += 1` пришлось бы копировать:

```text
1 + 2 + 3 + ... + 19 = 190
```

и общий порядок становится квадратичным.

Это не означает, что doubling всегда лучший production policy: он меняет memory overhead и зависит от allocator/workload. Здесь важен принцип geometric growth.

## Цель

Понять, почему тип в C связан не только с допустимыми операциями, но и с представлением значения в памяти и машинными операциями.

## Prerequisite check

1. Что делает `sizeof` по смыслу, даже если синтаксис пока не знаешь?
2. Чем build time отличается от run time?
3. Почему Python `int` не обязан вести себя как фиксированный машинный integer?

## Инженерный контекст

В Python число `10` выглядит как абстрактное целое. В C объявление

```c
int x = 10;
```

говорит компилятору больше: `x` имеет конкретный C-тип, занимает некоторое количество байтов и участвует в операциях согласно правилам этого типа.

Эта разница станет критичной для бинарных форматов, сетевых протоколов, указателей, переполнений и ABI.

## Базовые типы

Часто встречаются:

```c
char
short
int
long
long long
float
double
```

Есть signed и unsigned integer variants.

Важно: стандарт C задаёт отношения и минимальные диапазоны, но не обещает, что `int` везде строго 32 бита. Поэтому не надо заучивать «int = 4 bytes» как закон языка.

## `sizeof`

```c
printf("%zu\n", sizeof(int));
```

`sizeof` возвращает размер в байтах C-объекта/типа. Его результат имеет тип `size_t`, поэтому для `printf` используется `%zu`.

Размер `char` по определению равен `1` C-byte. Но C-byte не обязан совпадать с бытовым представлением «всегда 8 бит» на абсолютно любой мыслимой реализации. В нашем Linux/x86-64 окружении байт — 8 бит, и дальше курс будет опираться на это, когда перейдёт к системным API.

## Signed и unsigned

У unsigned integer арифметика определена по модулю `2^N`, где `N` — количество value bits соответствующего типа.

Например для условного 8-битного unsigned:

```text
255 + 1 -> 0
```

Это wraparound по правилам языка.

Для **signed integer overflow** в C ситуация принципиально другая: это undefined behavior. Нельзя считать, что signed overflow всегда «просто заворачивается».

Это один из первых примеров, почему машинная интуиция и правила C — не одно и то же.

## Диапазоны

Не вычисляй их вручную, если нужны реальные границы. Используй `<limits.h>`:

```c
#include <limits.h>

printf("INT_MIN = %d\n", INT_MIN);
printf("INT_MAX = %d\n", INT_MAX);
```

Позже познакомимся с `<stdint.h>` и типами вроде `uint32_t`, когда понадобится контролируемая ширина.

## Floating point

`float` и `double` предназначены для вещественных значений, но не представляют все десятичные дроби точно.

Поэтому:

```c
0.1 + 0.2
```

не стоит интерпретировать как точную школьную десятичную арифметику. IEEE 754 подробно разберём в модуле компьютерной архитектуры.

## Тип и объект

Полезная модель:

```text
имя переменной
    ↓
C object
    ↓
тип определяет допустимую интерпретацию/операции
    ↓
объект занимает байты
```

Пока не путай это с pointer/address — к адресам перейдём в Module 1.

## Conversion traps

C часто выполняет implicit conversions. Особенно неприятны сравнения signed и unsigned.

Например отрицательный `int` при определённых смешанных операциях может быть преобразован к unsigned, после чего результат сравнения удивит новичка.

Правило курса: не «лечить» такие случаи случайными casts. Сначала определить, какие значения домена вообще допустимы, и выбрать тип осмысленно.

## Упражнение

Напиши `type_probe.c`, который выводит:

- `sizeof(char)`, `sizeof(short)`, `sizeof(int)`, `sizeof(long)`, `sizeof(long long)`;
- `INT_MIN` и `INT_MAX`;
- `UINT_MAX`;
- результат `sizeof` для одной локальной переменной.

Затем **до запуска** предположи, какие размеры увидишь в своей Linux/x86-64 среде. После запуска сравни гипотезу с фактом.

Дополнительно создай `unsigned int u = UINT_MAX;`, увеличь его на 1 и объясни результат.

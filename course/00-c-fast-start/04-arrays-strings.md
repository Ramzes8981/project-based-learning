## Проблема 1: одной переменной мало

Если нужно хранить пять измерений, пять отдельных имён неудобны:

```c
int value0;
int value1;
int value2;
...
```

Нужна одна конструкция, содержащая несколько значений одного типа подряд.

## Ментальная модель массива

**Массив (array)** — фиксированное число элементов одного типа, к которым обращаются по номеру.

```c
int values[4] = {10, 20, 30, 40};
```

```text
index:   0    1    2    3
value:  10   20   30   40
```

Индекс `4` здесь уже вне массива.

## Граница — часть контракта

C не превращает `values[4]` в удобную автоматическую ошибку Python. Поэтому код обязан сам соблюдать допустимый диапазон.

Для количества элементов часто используют тип **`size_t`** — стандартный unsigned integer type для размеров объектов и результатов `sizeof`.

```c
size_t count = sizeof values / sizeof values[0];
```

Сейчас важно только: `count` хранит число элементов. Детальные integer-conversion правила будут позже.

## Проблема 2: как хранить текст

В базовом C нет отдельного встроенного `str` как в Python. Текст часто хранится как массив `char`.

```c
char name[] = "cat";
```

Но функции должны понять, где текст заканчивается. Для этого C string заканчивается специальным нулевым byte `0`, записываемым как `\0`.

```text
'c'  'a'  't'  '\0'
```

Такое представление называется **C string**.

## Почему размер массива и длина текста — не одно и то же

```c
char name[8] = "cat";
```

Массив содержит 8 элементов, но полезный текст сейчас — 3 символа до `\0`.

Не называем эти два числа одним словом «длина» без уточнения.

## Безопасное копирование на этом уровне

Для учебного фиксированного массива удобно сначала проверить, помещается ли весь текст вместе с конечным `\0`, и только затем копировать.

```c
size_t len = strlen(src);
if (len + 1 > sizeof dst) {
    /* reject */
}
```

`strlen` и `memcpy` объявлены в `<string.h>`.

Выражение `len + 1` здесь безопасно в нашем маленьком учебном input только потому, что `src` уже ограничен тестом. Общую проверку `size_t` overflow изучим перед dynamic allocation/network lengths.

## Неправильные mental models

> «Массив сам знает, сколько элементов я использовал».

Нет. Фиксированный массив знает только выделенное число элементов; «сколько сейчас занято» часто нужно хранить отдельно.

> «C string — просто array char».

Недостаточно. Для string-функций должен существовать достижимый `\0` внутри допустимого массива.

## Практика

1. Создай `int values[5]` и выведи элементы циклом.
2. Создай `char word[8]` и безопасно запиши в него короткое слово.
3. Отдельно храни `used`, сколько элементов массива записей сейчас реально занято.
4. Проверь условие до добавления нового элемента: если `used == max_items`, добавление запрещено.

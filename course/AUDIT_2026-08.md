# Course Audit — Self-Contained v3 (2026-08)

## Verdict

До v3 репозиторий уже имел хороший dependency-checked syllabus, но обязательная теория всё ещё находилась в CS50/Dive Into Systems/OSTEP/Beej/Nand2Tetris/tutorials/man pages.

Это означало: курс был качественной картой и системой заданий, но не самостоятельным учебным пространством.

V3 меняет **контентный слой**, не базовую педагогическую модель.

## Зафиксированные решения

- основной язык: русский + английский термин при первом важном упоминании;
- required theory внутри repo;
- external links только optional/reference;
- one `.md` = один mobile-first learning cycle;
- exercise solutions рядом с уроками;
- milestone code пишет ученик с нуля;
- project folder даёт SPEC/ACCEPTANCE/TESTS/HINTS;
- public tests видимы; review может добавлять unseen edge cases;
- Python допустим как вспомогательная test/load tooling;
- C17 + WSL2/Linux — основная low-level среда;
- Rust stable/Cargo — обязательный Systems Bridge после C memory/hash table;
- Rust не дублирует весь C-course.

## Curriculum structure

Core теперь содержит 11 последовательных blocks, если считать `1B` отдельным bridge:

```text
0 C Fast Start
1 Memory & Data Structures
1B Rust Systems Bridge
2 Unix & Shell
3 Computer Architecture
4 Virtual Memory & Allocators
5 Networking & Concurrency
6 OS & Isolation
7 Filesystems & Databases
8 Binaries & Debugging
9 Integration & Architecture
```

В module directories находится **95 lesson/checkpoint Markdown files** по основной последовательности, плюс отдельные solution/project specification artifacts.

## Почему внешние tutorials больше не являются dependency

Некоторые сильные проекты сохранены как optional reading/ideas, но mandatory scope имеет собственную спецификацию:

- Hash Table — course linear-probing spec;
- Shell — course grammar + FD/process spec;
- Nand2Tetris — optional, mandatory architecture project = Tiny16;
- allocator — course arena over mmap;
- concurrent server — course framed KV protocol;
- old container tutorial — replaced by namespace/cgroup v2 isolation spec;
- FUSE — small current guided lab, not full old tutorial;
- DB tutorial — course SimpleDB file/page/B+tree spec;
- C++ debugger tutorial — replaced by C/Linux/x86-64 `minidbg-c` spec;
- architecture capstone — course-owned persistent KV service.

## Scaffolding audit

### Module 0 → 1

Fixed MiniKV intentionally exposes limitations: fixed capacity + linear search + pass-by-value. Module 1 introduces pointers/dynamic memory/hash table only after those problems exist.

### Module 1 → Rust Bridge

C ownership/lifetime mistakes are learned first. Rust then maps them to move/borrow/lifetime/Drop/unsafe concepts, so borrow checker rules have a concrete reference model.

### Rust Bridge → Unix

Course returns to C for POSIX/process APIs, while keeping Rust ownership concepts available for comparison. Rust does not interrupt low-level C continuity with duplicated projects.

### Unix → Architecture → VM/Performance

Shell teaches process/syscall model. Tiny16/ABI gives machine model. Only then virtual translation/cache/allocator are combined.

### Networking → OS

Thread/race/condvar basics appear in service context before deeper scheduling/deadlock/IPC/namespace work.

### Storage

Filesystem/durability comes before persistent DB page format; pager comes before B+tree; B+tree comes before WAL/recovery concepts.

### Debugger

ELF/PIE comes before ptrace; ptrace state loop before memory/registers; those before breakpoints; breakpoints before DWARF/security mitigations.

### Capstone

No new giant technology stack. It integrates already learned pieces and tests evidence-driven architecture.

## Hidden prerequisites removed

- bit masks before `termios`;
- pointers/ownership before Linux APIs using buffers/structs;
- explicit FD lifecycle before pipes;
- architecture/ABI before debugger;
- virtual memory before allocator;
- synchronization before OS deadlock/isolation;
- robust TCP stream framing before concurrency;
- binary serialization before DB storage;
- no C++ prerequisite in core debugger.

## Mobile audit

Lesson files include time estimates, short sections and phone suitability markers. Wide tables are avoided in lesson bodies; diagrams are mostly vertical/textual. Major project work remains PC-first.

## Remaining external dependency class

The repo is not literally offline-complete for operating-system/tool installation. Internet may still be needed to install packages/toolchains or consult exact current platform docs.

That is intentional: API/standards documentation remains an engineering reference. A learner should be able to understand and complete the **required conceptual/implementation path** without an external textbook/course.

## Maintenance rule

If future lesson requires an external article to explain a mandatory concept, this is a course defect. Bring the needed explanation into the lesson, then keep the external link only as optional/reference.

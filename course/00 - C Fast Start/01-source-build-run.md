## Что мы пытаемся понять

Ты умеешь писать текст программы. Но процессор не исполняет текст `main.c` напрямую. Значит, между исходным файлом и запуском должен быть перевод.

## Проблема

Создай мысленную модель:

```text
main.c
  │  обычный текст
  ▼
?
  ▼
./hello
  │  уже запускается
```

Нам пока не важно, какие внутренние стадии есть у `?`. Нужно понять только необходимый переход.

## Интуиция

Python обычно запускается через interpreter/runtime, который читает программу в удобной для него форме. В C типичный путь другой: специальная программа заранее переводит исходный текст в исполняемый файл.

Эта программа называется **компилятором (compiler)**.

```text
C source
  ↓ compiler
executable file
  ↓ run
observable result
```

## Первый пример

Создай `hello.c`:

```c
#include <stdio.h>

int main(void)
{
    puts("hello");
    return 0;
}
```

Собери:

```bash
cc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello
```

Запусти:

```bash
./hello
```

Пока воспринимай `#include <stdio.h>` как способ сообщить программе о стандартной функции `puts`. Почему declarations и headers нужны, разберём в 0.5.

## Что означает команда сборки

Нам нужны только четыре части:

```text
cc                 программа-компилятор
-std=c17           используем правила C17
-Wall ...          просим показывать полезные предупреждения
hello.c            входной текст
-o hello           имя результата
```

Не запоминай список флагов наизусть. В курсе они будут стандартной baseline-командой.

## Ошибка компиляции и ошибка выполнения — разные вещи

Если удалить `;`, компилятор не сможет корректно разобрать программу. Исполняемый файл с этой новой версией вообще не появится.

Если программа успешно собралась, но выводит не то значение, это уже другая категория проблемы: код допустим для компилятора, но поведение неверно для нашей задачи.

## Неправильная mental model

> «Компилятор запускает мою программу».

Нет. В этой модели компилятор **создаёт** исполняемый файл. Затем ты отдельно запускаешь результат.

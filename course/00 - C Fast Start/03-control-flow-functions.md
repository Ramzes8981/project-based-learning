## Проблема

Даже маленькая программа быстро превращается в длинный `main`: проверить ввод, найти запись, решить, что делать, вывести результат.

Если всё смешано, трудно ответить: где именно сломалась логика?

## Интуиция

Разделяем программу на маленькие операции с понятным входом и результатом. В C для этого используем **функции (functions)**.

```c
int bigger(int a, int b)
{
    if (a > b) {
        return a;
    }
    return b;
}
```

## Ветвление

`if` выбирает один путь по условию:

```c
if (score >= 60) {
    puts("pass");
} else {
    puts("retry");
}
```

Главный вопрос не «какой синтаксис у if», а: **какой факт делает один путь допустимым, а другой — нет?**

## Повторение

Если действие нужно повторить для нескольких номеров:

```c
for (int i = 0; i < 3; ++i) {
    printf("i=%d\n", i);
}
```

Здесь важен boundary: выполняются значения `0`, `1`, `2`; при `i == 3` условие уже false.

## Функция как маленький контракт

Перед написанием функции сформулируй:

```text
что получает?
что возвращает?
какие случаи считаются допустимыми?
```

Такой вопрос позже перерастёт в API design, но сейчас нужен лишь для ясности.

## Неправильная mental model

> «Функция полезна только чтобы не копировать код».

Reuse полезен, но ещё важнее boundary: функцию можно рассуждать и проверять отдельно от всего `main`.

## Практика

Напиши функцию:

```c
int clamp_score(int score);
```

Поведение:

- меньше `0` → `0`;
- больше `100` → `100`;
- иначе вернуть исходное значение.

В `main` проверь минимум пять случаев: ниже границы, обе границы, середину и выше границы.

Разбор: [`03-control-flow-functions.solution.md`](03-control-flow-functions.solution.md).
